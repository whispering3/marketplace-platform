# Security Policy

## Supported versions

Security fixes are provided for the latest code on the `main` branch while the project remains experimental.

## Reporting a vulnerability

Do **not** file a public issue for a security vulnerability. Report it privately to the repository owner through GitHub's private vulnerability reporting feature. If that feature is unavailable, contact the owner through the contact method listed in the repository profile.

Include a clear description, affected area, reproduction steps, impact and any suggested mitigation. Do not include real credentials, private keys, recovery phrases, wallet material, personal data or production host names.

You should receive an acknowledgement within seven days. Please allow reasonable time for investigation and remediation before public disclosure.

## Scope

High-priority reports include authentication and authorization bypasses, session handling, injection, cross-site request forgery, unsafe redirects, wallet RPC exposure, financial-accounting errors, secret leakage and supply-chain compromise.

This repository is experimental. A report or merge must never be interpreted as a guarantee that a deployment is secure for real funds or production workloads.
